DEMO 01 / 議事録

散らばったメモを次の行動が分かる議事録へ。

こんな場面を想定しています

営業担当者がA社との商談を終えた場面。メモには要望と宿題が混在しています。社内共有する前に、情報を整理する想定です。

INPUT / 素材

まずは、記録を集める。

文章が整っていなくても、事実が分かるメモを用意します。入力前に、社外に出せない情報や個人情報の扱いを確認します。

録音の利用は相手への説明や社内ルールを確認。ここでは文字のメモだけを扱います。

DEMO 02 / 提案書

顧客の課題から提案の筋道をつくる。

こんな場面を想定しています

B社から「新人の問い合わせ対応を安定させたい」と相談された場面。相談内容と自社が対応できる範囲を素材に、提案の構成を考えます。

INPUT / 素材

課題と制約を
先にそろえる。

AIに任せる前に、顧客の困りごとと提案できる範囲を整理します。何を解決する提案かを明確にするのは、顧客を知る担当者の役割です。

価格・納期・契約条件は未確認のまま断定させません。

AI DRAFT / 整理例

白紙からではなく

課題・目指す状態・進め方・確認事項の順に並べます。AIの案をたたき台にして、担当者が顧客の事情に合わせて具体化します。

指示の例：「以下の条件だけを使って提案の構成を作成し、成果や削減率は断定しないでください。」

IDM / WORK SAMPLE架空の業務例

問い合わせ対応を整える提案構成

01　現状の課題

回答を探す手間と、ベテランへの確認の集中。

02　目指す状態

新人が参照先を見つけ、判断できない質問は適切に引き継げる。

03　小さく試す内容

よくある質問を一つ選び、既存の回答からFAQの下書きを作成。担当者が確認して試す。

04　事前に決めること

対象業務、参加者、資料の利用可否、回答の承認担当。

費用・実施条件は、正式な提案時に確認して記載します。

DEMO 03 / マニュアル

ベテランの説明を誰もが確認できる手順へ。

こんな場面を想定しています

C社の問い合わせ受付業務。新人が同じ内容を何度も質問しているため、経験者の説明を、迷ったときの確認先まで分かる手順に整理します。

INPUT / 素材

経験者の判断を
言葉にして集める。

操作の順番だけでなく、何を確認しているか、どんなときに判断を止めるかも聞き取ります。既存の正式なルールと合わせて用意します。

この例は一般的な受付業務です。設備操作や安全に関わる手順には、別途専門的な検証が必要です。

IDM / WORK SAMPLE架空の業務例

担当者から聞き取ったメモ

まず会社名と相談の内容を確認。
既存のお客様なら過去の対応を見る。
よくある質問は承認済みの回答集を使う。
金額や納期はその場で約束しない。
分からないものは責任者へ。
対応した内容は最後に記録する。

聞き取った内容が正式な運用ルールと一致するかも確認します。
AI DRAFT / 整理例

手順と、迷ったときの
分岐を見える形に。

経験者の説明を、番号付きの手順に変えます。判断できないときの行動も明記して、新人が自己判断で進めないようにします。

指示の例：「操作手順、判断の分岐、禁止事項に分けて整理し、不明な承認者名は要確認にしてください。」

IDM / WORK SAMPLE架空の業務例

問い合わせ受付の手順 / 下書き

01　受け付ける

会社名と相談内容を確認。既存のお客様の場合は、閲覧権限のある過去の対応履歴を確認。

02　回答できるか判断する

承認済みの回答集で対応できる → 回答する。
回答集にない・判断に迷う → 責任者へ引き継ぐ。

03　記録する

相談内容、回答した内容、引き継ぎ先と未対応事項を記録。

金額・納期を独断で約束しない。責任者の氏名と連絡方法は要確認。
HUMAN REVIEW / 確認

実際の現場で
使えるかを試す。

経験者が内容を確認した後、新人にも手順を追ってもらいます。迷った箇所を修正してから、社内の正式な手順として扱います。

作成して終わりではなく、更新担当と見直すタイミングも決めます。
